## امکانات

- پراکسی‌های upstream از نوع HTTP / HTTPS و SOCKS5 (با نام کاربری و رمز عبور، IPv4 و IPv6) و SOCKS4 / SOCKS4a
- یک رلهٔ محلی که همهٔ اتصال‌های دیسکورد از آن عبور می‌کنند
- پراکسیِ سراسریِ ویندوز به‌صورت اختیاری، که فقط خودت می‌توانی روشنش کنی
- اجرا و بستن دیسکورد از داخل برنامه، با اعمال پراکسی
- حالت Strict — به‌صورت پیش‌فرض خاموش
- وضعیت زنده: حالت رله، پراکسیِ فعال، شمارندهٔ اتصال‌ها
- کوچ‌شدن به سینی (tray) با منوی Connect / Disconnect / Quit
- به‌روزرسانی خودکار: بررسی نسخهٔ جدید و نصب آن از داخل برنامه

## چطور کار می‌کند

```
Discord ──► 127.0.0.1:17999 (رلهٔ محلی) ──► پراکسیِ شما ──► discord.com
```

1. یک پراکسی اضافه و فعال می‌کنید.
2. **رلهٔ محلی** را روشن می‌کنید؛ یک پراکسیِ HTTP که روی `127.0.0.1` گوش می‌دهد.
3. دیسکورد را از داخل برنامه اجرا می‌کنید (با فلگ `--proxy-server`)، یا سوییچ
   **Windows system proxy** را روشن می‌کنید تا دیسکوردی که خودتان از Taskbar باز
   می‌کنید هم از همین رله رد شود.

رله لازم است چون خودِ Chromium نمی‌تواند نام کاربری/رمز عبورِ پراکسی را بفرستد و
اتصال SOCKS5ِ دارای احراز هویت را هم پشتیبانی نمی‌کند. رله این کارها را انجام می‌دهد و
همه‌چیز را از یک دروازهٔ واحد رد می‌کند.

### انواع پراکسی

| نوع | پشتیبانی |
| --- | --- |
| HTTP / HTTPS | تونل‌زنیِ `CONNECT` همراه با احراز هویت Basic |
| SOCKS5 | نام کاربری / رمز عبور، IPv4 و IPv6 |
| SOCKS4 / SOCKS4a | ✔ |

### حالت Strict

به‌صورت پیش‌فرض خاموش است. وقتی دیسکورد را از داخل برنامه اجرا می‌کنید، این فلگ به آن
داده می‌شود: هر بسته‌ای که نتواند از پراکسی رد شود، دور ریخته می‌شود به‌جای آنکه مستقیم
نشت کند. صدای دیسکورد روی UDP است و معمولاً با روشن بودن این گزینه کار نمی‌کند؛ اگر
صدا می‌خواهید، آن را خاموش کنید.

## پراکسی سیستم ویندوز

سوییچ **Windows system proxy** همهٔ برنامه‌های سیستم را به رلهٔ محلی اشاره می‌دهد:

- **هرگز به‌صورت خودکار روشن نمی‌شود** — فقط کلیکِ خودِ شما روی این سوییچ، یا روی
  دکمهٔ *Start with system proxy* در پنجرهٔ به‌روزرسانی، می‌تواند آن را فعال کند؛
- **وقتی ویندوز از اسکریپت PAC استفاده می‌کند رد می‌شود** (`AutoConfigURL`) — در این
  حالت ویندوز اصلاً پراکسیِ ساده را نادیده می‌گیرد، پس برنامه به‌جایش خطا گزارش می‌کند؛
- **به‌صورت خودکار بازگردانده می‌شود** وقتی رله متوقف می‌شود یا برنامه بسته می‌شود، تا
  سیستم با یک پراکسیِ مرده گیر نکند.

### Update.exe و نشستِ به‌روزرسانی

`Update.exe` یک برنامهٔ .NET است، نه Chromium — فقط تنظیمات پراکسیِ خودِ ویندوز را
می‌خواند و کلاً از کنار رله رد می‌شود. وقتی دیسکورد را اجرا می‌کنید، برنامه پیشنهاد
می‌دهد پراکسیِ سیستم **فقط برای همان به‌روزرسانی** روشن شود:

- پنجره دکمهٔ *OK* (کاری نکن) و دکمهٔ *Start with system proxy* را دارد؛
- بعد از شروع، این نشست **۲۰ ثانیه پس از بی‌حرکت شدن به‌روزرساننده**، پراکسیِ سیستم را
  دوباره خاموش می‌کند؛
- اگر خودتان از قبل پراکسیِ سیستم را روشن کرده باشید، این پیشنهاد هرگز نمایش داده
  نمی‌شود و هیچ‌چیز دستکاری نمی‌شود.

## به‌روزرسانی خود برنامه

دکمهٔ **Check for update** در نوار بالا، آخرین انتشار را از GitHub می‌پرسد:

| برچسب | معنا |
| --- | --- |
| Check for update | هنوز بررسی نشده، یا بررسی ناموفق بوده |
| Latest version | این نسخه آخرین نسخه است |
| Update to vX.Y.Z | نسخهٔ جدیدتری منتظر است — کلیک روی آن، نصب‌کننده را دانلود و برنامه را دوباره اجرا می‌کند |

در زمان راه‌اندازی هم برنامه بی‌صدا در پس‌زمینه بررسی می‌کند؛ اگر آن بررسی شکست بخورد
هیچ‌چیزی تغییر نمی‌کند.

## نصب

فایل `Discord.Proxy_<version>_x64-setup.exe` را از صفحهٔ
[Releases](https://github.com/peditx/discord-proxy/releases) دانلود و اجرا کنید.
نصب‌کننده از نوع NSIS است؛ به‌روزرسانی‌هایی که از داخل برنامه نصب می‌شوند همان فایل را
استفاده می‌کنند.

## تنظیمات

تنظیمات و پراکسی‌های ذخیره‌شده در اینجا نگهداری می‌شوند:

```
%APPDATA%\com.peditx.discordproxy\store.json
```

## بیلد

این برنامه **فقط روی GitHub Actions** بیلد می‌شود — [.github/workflows/build.yml](.github/workflows/build.yml).
هر push روی `main` نصب‌کنندهٔ NSIS را به‌صورت Artifact می‌گذارد؛ گذاشتن تگ (`v1.2.3`)
همان فایل را به Release اضافه می‌کند.

بیلد محلی (ویندوز، اختیاری):

```bash
cargo tauri build
```

## توسعه

```bash
cargo tauri dev
```

مرحلهٔ build فرانت‌اند وجود ندارد — HTML/CSS/JS خامِ داخل [src/](src/) همان‌طور که هست
بارگذاری می‌شود و از طریق `window.__TAURI__.core.invoke` با بک‌اند Rust حرف می‌زند.

### ساختار پروژه

```
src/                     رابط کاربری (بدون مرحلهٔ build)
src-tauri/src/
  lib.rs                 وضعیت + دستورات Tauri
  relay.rs               رلهٔ محلی (HTTP معمولی و CONNECT)
  dial.rs                اتصال به upstream: HTTP / SOCKS5 / SOCKS4
  sys.rs                 رجیستری ویندوز، پیدا/اجرا کردن دیسکورد
  store.rs               مدل‌ها + ذخیره‌سازی JSON
.github/workflows/
  build.yml              بیلد و انتشار ویندوز
docs/
  screenshot.png         تصویر بالا
```
